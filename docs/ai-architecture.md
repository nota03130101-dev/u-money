# U Money 最小 AI 后端架构

## 1. 目标与边界

本阶段只为 U Money 设计两个 AI 功能：

1. 自然语言智能记账：把“今天午饭 32 元”解析成待确认的记账记录。
2. 月度消费总结：根据一个月的汇总数据生成简短、客观的文字总结。

第一版 AI 后端保持为一个 FastAPI 服务，不训练模型，不使用 RAG、向量数据库、多 Agent、消息队列、微服务集群或 Kubernetes。

AI 服务不直接替用户保存、编辑或删除账单。所有 AI 生成结果必须先经过程序验证；自然语言记账还必须由用户确认后，才能通过现有 Supabase 流程保存。

## 2. 最小组成

```text
手机或电脑浏览器
  ├─ 现有记账功能 ───────────────> Supabase Auth + records 表
  └─ AI 请求 + Supabase 登录凭证 ─> FastAPI AI 服务
                                      ├─ 验证用户身份
                                      ├─ 用 Pydantic 验证输入和输出
                                      ├─ 调用一个大模型 API
                                      └─ 月度总结时只接收前端计算的汇总数据
```

- 前端：继续使用现有 HTML、CSS 和 JavaScript。
- Supabase：继续负责注册、登录、会话和 `records` 数据。
- FastAPI：提供三个 HTTP 接口，处理身份验证、数据最小化、模型调用和错误处理。
- Pydantic：定义数据格式并验证模型返回内容。可以把它理解为“数据检查表”。
- 大模型 API：只负责语言理解和文字生成，不负责权限判断、精确金额计算或数据库写入。
- pytest：在不调用真实模型的情况下自动测试后端。

## 3. 数据流

### 3.1 自然语言智能记账

1. 用户必须先在 U Money 登录。
2. 前端从 Supabase 当前会话取得短期访问令牌。
3. 前端把自然语言、参考日期、时区和访问令牌发送到 `POST /ai/parse-transactions`。
4. AI 服务验证令牌，得到用户编号，但不记录邮箱和完整令牌。
5. AI 服务检查文本长度和请求格式，然后调用模型。
6. 模型只返回结构化候选记录。
7. Pydantic 和业务规则再次验证日期、类型、金额、类别和条数。
8. AI 服务把候选记录返回前端，不写入数据库。
9. 前端显示确认界面。用户确认后，继续使用现有 Supabase 用户会话写入 `records` 表。
10. Supabase RLS 继续保证记录属于当前用户。

这样设计可以防止模型误解一句话后直接形成错误账单。

### 3.2 月度消费总结

1. 用户选择月份，前端从当前用户可见的记录中计算总收入、总支出、余额变化、记录数量、类别合计和上月变化。
2. 前端把这些汇总数据与 Supabase 访问令牌发送到 `POST /ai/monthly-summary`，不发送完整账单、日期明细或备注。
3. AI 服务验证用户身份与汇总数据格式，但不读取 Supabase `records` 表。
4. 如果记录数量为零，后端直接返回清晰空状态，不调用模型。
5. 如果有数据，只把前端计算出的汇总结果发送给模型。
6. 模型生成简短总结，Pydantic 验证格式和安全语言后返回前端。
7. 前端显示普通统计与 AI 草稿；总结不会自动写入数据库。

金额统计由 Python 完成，模型只负责组织语言。这样可以避免模型算错钱。

## 4. 用户身份验证

AI 接口第一版只向已登录用户开放。前端请求需要携带：

```http
Authorization: Bearer <Supabase access token>
```

AI 服务必须验证：

- 签名有效；
- 令牌没有过期；
- 签发者是当前 U Money 的 Supabase 项目；
- 用户角色是已登录用户；
- 令牌中的用户编号存在。

建议使用 Supabase 的公开 JWKS 验证签名，并缓存公开密钥。JWKS 是“供后端检查令牌真假的公开钥匙列表”。如果当前 Supabase 项目仍使用不适合 JWKS 的旧令牌方式，应改为调用 Supabase Auth 用户验证接口，不要把 JWT Secret 放到前端。

AI 服务使用访问令牌确认调用者已登录，但月度总结不接受前端传来的 `user_id`，也不需要 `service_role` 密钥。

## 5. 为什么模型 API 密钥不能放在前端

浏览器中的 HTML 和 JavaScript 会下载到用户设备，任何人都能查看。即使把密钥换个变量名或做简单编码，也只是“把钥匙藏在透明盒子里”。

前端保存模型密钥会导致：

- 他人复制密钥并消耗额度；
- 他人绕过 U Money 直接调用模型；
- 无法可靠限制每个用户的调用次数；
- 密钥可能出现在浏览器记录、截图或公开 GitHub 仓库；
- 密钥泄露后需要立即停用和更换。

因此模型 API 密钥只通过 AI 服务的环境变量提供，并且永远不返回给前端。

## 7. Prompt 版本管理

Prompt 是发给模型的任务说明。Prompt 不直接写在路由函数里，而是放入版本目录：

```text
prompts/parse-transactions/v1.txt
prompts/monthly-summary/v1.txt
```

规则：

- 每次修改行为时创建新版本，例如 `v2.txt`；
- 旧版本保留，方便比较测试结果和回退；
- 响应和日志只记录 `prompt_version`，不记录完整 Prompt 或用户输入；
- 版本变更必须配套固定测试样例；
- 第一版由配置指定启用版本，不做复杂实验平台。

## 8. 超时、错误与降级

- 单个模型调用建议最多 15 秒；
- 整个 AI 请求建议最多 20 秒；
- 只对明确的临时网络错误重试一次，并且总时间不能超过 20 秒；
- 结构化输出不合格时最多允许一次修复请求；
- 超时、额度不足或模型服务异常时返回统一错误，不把供应商原始错误暴露给前端。

降级方式：

- 智能记账不可用：显示“智能解析暂时不可用”，保留现有手动记账表单。
- 月度总结不可用：继续显示现有程序计算出的月度收入、支出、余额和分类图表，只隐藏 AI 文字总结。
- AI 服务不可用不得影响登录、普通记账、筛选、统计和 CSV 导出。

## 9. 本地开发

后续实现时建议：

1. 在 `backend` 中创建 Python 虚拟环境。虚拟环境是项目专用的 Python 工具箱。
2. 把本地密钥放在未提交的 `.env` 中，只提交不含真实值的 `.env.example`。
3. 使用 `uvicorn` 启动一个 FastAPI 服务。
4. 前端仍可用本地静态服务器打开。
5. 后端 CORS 只允许本地前端地址和正式 GitHub Pages 地址。CORS 是浏览器对“哪些网页可以调用后端”的限制。
6. 测试默认使用假的模型客户端，不消耗真实模型额度。

建议的环境变量名称：

```text
MODEL_API_KEY=
MODEL_NAME=
SUPABASE_URL=
SUPABASE_PUBLISHABLE_KEY=
SUPABASE_JWT_ISSUER=
ALLOWED_ORIGINS=
ACTIVE_PARSE_PROMPT_VERSION=v1
ACTIVE_SUMMARY_PROMPT_VERSION=v1
```

## 10. 简单部署

第一版只部署一个 FastAPI 容器到支持 HTTPS、环境变量和健康检查的托管平台：

1. 使用一个 `Dockerfile` 打包 `backend`；
2. 平台启动一个实例，不使用集群；
3. 在平台控制台填写模型密钥等环境变量；
4. 健康检查访问 `GET /health`；
5. 只允许 GitHub Pages 正式域名调用；
6. 前端只保存公开的 AI 服务地址，例如 `https://api.example.com`；
7. 设置模型供应商的消费上限和告警。

如果以后单实例承载不了实际用户，再根据真实使用量升级。第一版不提前引入 Redis、消息队列或 Kubernetes。

## 11. 测试策略

使用 pytest，默认不调用真实模型：

- 数据模型测试：正常输入、空文本、超长文本、非法金额、非法日期和多条记录。
- 路由测试：三个接口的状态码和响应格式。
- 身份测试：无令牌、过期令牌、错误签发者和有效令牌。
- RLS 集成测试：账号 A 无法读取账号 B 的记录。
- 模型适配测试：使用固定假响应验证解析和总结。
- 结构验证测试：缺字段、多字段、错误类型和模型返回非 JSON。
- 超时测试：模型无响应时在规定时间内降级。
- 限流测试：超过次数后返回 429。
- 隐私测试：日志中不出现令牌、邮箱、原始记账文本、备注或金额。
- 端到端人工测试：使用虚构账单验证手机和电脑流程。

真实模型测试只保留少量、人工触发的非敏感样例，不进入默认测试。
